## Промах прогона (мой, не кода)

Первый заход WA2 на стейдже дал FAIL «не уложился в отведённое время». Причина
оказалась правильным поведением: демон работал под УЗКИМ `permissions.json`

некому, роль веб-морды в том прогоне не игралась. Журнал демона показал это
прямо: `? Bash — спрашиваю разрешение в чате` → `deny (ответ из чата: отказ)`.

Урок для сценария: **WA2 и WA12 требуют РАЗНЫХ конфигураций разрешений**, и это
надо держать в голове при прогоне — иначе один тест выглядит как поломка другого.

## Что нашлось глазами и не ловилось скриптом

**1. Опрос не запускался вовсе.** `pollRequests: 0` при идущем ходе: признак
«ход идёт» брался из `iterations[].running` ChatProvider'а, а в **chat-v2**
состояние хода живёт в своём редьюсере. Исправлено на общий стрим-статус
`useStreamingGlobal` (execaiui `627ea9a`). Скрипт этого поймать не мог в
принципе — он ходит в API напрямую, минуя условие опроса.

**2. Service worker отдавал старый бандл.** После выкатки страница продолжала
грузить `index.CzXyRiRI.js` из кэша PWA, и правка «не работала». Лечится
`navigator.serviceWorker.getRegistrations() → unregister()` + `caches.delete()`.
**Проверять фронт на DEV без этого нельзя** — иначе смотришь на вчерашний код.

**3. Подписи кнопок обещали не то, что делает код.** «Сессия — разрешить до
перезапуска агента»: на деле `webApprover` живёт **одну задачу**. И «Сессия», и
«Всегда» открывают **инструмент целиком**, а не показанную команду, — из текста
это не следовало. Переписано по TUI (`approve.*` в i18n) и по факту:
«Разово» · «Весь Write в этой задаче» · «НАВСЕГДА» · «Отклонить»
(agents-vbai `78fa552`, execaiui `1dc5b3e`). Значения ответов
(`once/session/always/deny`) НЕ менялись. Уточнение: выше я считал, что их
разбирает выпущенный v6.17 — **это неверно**, релиз опубликован 05.08 02:18 МСК,
а askweb лёг в 04:19. Публичного демона с вопросами ещё нет; словарь заморозит
первый релиз с ними (v6.18).

## Баг, найденный прогоном WA13 (и закрытый)

Первый заход: **два вопроса на две ОДИНАКОВЫЕ команды.** Модель сменила
косметическое поле `description` между вызовами, а ключ «точного вызова» был
сырой `name+"|"+json(args)` — у TUI ([s]) та же беда. Ключ канонизирован
(`agent/exactkey.go`): description выброшен, поля отсортированы, HasExact
канонизирует обе стороны — старые записи в permissions.json продолжают
узнаваться. Печать: `TestExactKey_CosmeticsDontChangeIt`,
`TestHasExact_LegacyEntriesStillMatch`, WA13 живьём на DEV и STAGE.
