## WA2, заход №1 (R6.13) — 🔴 FAIL, найден баг

Полный живой конвейер: `POST /aichat-vbai/stream` c
`tools:[{tool_id:"agent",alias:<agent_id>}]`, MiniMax-M3.

Что ДОКАЗАЛ заход (артефакты `wa2_stream.log`, `wa2_history.json`):
- регистрация тулсета работает: модель ПОЛУЧИЛА `run_on_agent`;
- подстановка `{alias}` работает: во всех вызовах `agent=0ba206a4…` (наш id,
  не выдуманный);
- демон получил и ВЫПОЛНИЛ все 3 задачи (424/1648/225 символов).

Что сломано: aihandler читает ответ инструмента как SSE
(`{"function_result":"output","content":<base64>}`), а `/tasks/run` отвечал
голым JSON → модель видела «(empty output — command returned no data)» и
отвечала «агент недоступен» при выполненной задаче.

Фикс: agents-vbai `4790b6b` — SSE по контракту + keepalive каждые 5с +
отказы адресации error-чанком (HTTP 400 aihandler передаёт модели без текста
тела). Контракт закреплён юнитом `TestSSE_ContractShape`.

## WA6, заход №1 (R6.14) — 🔴 FAIL, найден баг №5 (потеря задачи)

Демон убит → `/tasks/run` → ожидали отказ ≤15с, получили **110.3с** и текст
«агент ВЗЯЛ задачу» при мёртвом агенте. Причина: long-poll живёт за шлюзом,
разрыв клиента до пода не доезжает — зомби-хендлер досиживает wait, Redis-wake
будит его, он помечает задачу `picked` и отдаёт список в мёртвое соединение.
**Задача терялась навсегда** (picked, никем не исполнена, re-выдачи нет).

Фикс: ack-механика (agents-vbai `68483a6` + agent-vbai `1b42c8b`) — выдача
из инбокса больше не меняет статус; `picked` ставит только живой демон явным
`POST /inbox/ack`; демон выполняет строго подтверждённое сервером. Юниты:
`TestAckTasks_ExecutesOnlyConfirmed`, `TestAckTasks_NetworkFailureMeansNoTasks`.
Заход №2: 12.2с + подхват после рестарта — PASS.
