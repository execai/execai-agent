## Что нового

### Claude Code CLI: агент снова умеет править и запускать

Источник `claude-cli` (квота Pro/Max через установленный Claude Code)
работал как читалка: в режиме `claude -p` Claude Code некого спросить, и
он молча отклонял любую правку файла и любую команду, если они не были
заранее разрешены в `~/.claude/settings.json`.

Теперь каждый такой запрос приходит в обычное окно подтверждения агента —
в терминале, в панели редактора и в веб-канале — и решается по тому же
уровню безопасности, что и собственные инструменты execai. Работа внутри
проекта молчалива, правки и опасные команды спрашиваются, ответ
«всегда» действует и на инструменты execai, и на инструменты claude.

Действия claude видны карточками инструментов, как и свои: что прочитал,
что поменял, что запустил. Изменённые файлы попадают в список правок
редактора.

### Свежий Claude Code вместо забытого старого

Агент брал первый `claude` из PATH — часто это глобальная установка
месячной давности, которая сама не обновляется, хотя в редакторе стоит
свежий Claude Code. На старом CLI алиас `opus` даёт прошлое поколение, а
новые модели он не принимает вовсе.

Теперь агент выбирает самую новую установку из найденных: PATH,
`~/.local/bin`, `~/.claude/local` и Claude Code, встроенный в расширения
VS Code, Cursor, VSCodium и ExecAI Studio. Свой путь можно закрепить
переменной `EXECAI_CLAUDE_BIN`. `/connect claude-cli` показывает, какой
бинарь выбран.

### Новые модели в каталоге claude-cli

Алиасы `opus`, `sonnet`, `fable`, `haiku` и закреплённые Claude Opus 5.5,
Sonnet 5.5, Fable 5.1 и Haiku 4.5 вместо поколения 4.x. Алиасы идут за
версией Claude Code — с обновлённым CLI `opus` — это Opus 5.5.

### Ошибки claude — ошибки, а не ответ

Отказ CLI (например, «эта модель требует более новой версии Claude
Code») раньше печатался так, будто это ответ модели. Теперь это ошибка
с указанием версии и пути бинаря, который её вернул.
