## What's new

**7.2 is the first public release of the seventh line.** Everything at once: ExecAI models by plan (your own keys need none), migration from another agent, sync with a passphrase and per-project sync, tasks from the site right in the editor panel, parallel subagents you can watch, and the agent panel in a browser (`execai ui`). The VS Code extension 0.2.36 and ExecAI Studio update together with the agent.

### Subagents: several agents work at the same time

The agent hands subtasks to subagents, and they run in parallel: "study the
handlers", "check the tests", "find where the config is read" — three
subagents in the time of one. Each has its own loop, its own context and
its own transcript; the main agent gets back only the result.

- **Read or act.** By default a subagent only reads. In `write` mode it
  edits files and runs commands — and asks for permission in the same place
  the main agent does, marked "agent «name» is asking".
- **In the background.** A subagent can be started without waiting: the
  agent keeps working, and the result arrives on its own as a separate
  message when the subagent finishes (or the agent waits for it with the
  `TaskWait` tool).
- **Its own model and directory.** `model: fast` picks the cheapest model
  of the current source for a simple search; a specific model can be named
  too. The directory is a subfolder of the project; a subagent never climbs
  above the project.
- **You can see who is doing what.** In the terminal, the **Agents** block
  above the input (state, step, last tool, time) and "agents: 2▶ 1✓" in the
  status line. `/agents` lists them with results, `/agents open <n>` shows
  everything a subagent did, `/agents stop <n>` stops it. The panel in
  VS Code, ExecAI Studio and `execai ui` shows the same list with a
  transcript tab; the machine card in the web console shows how many are
  running and what is done.
- **Limits.** By default 15 steps and 5 minutes per subagent (steps can go
  up to 50), up to 4 at once (`EXECAI_SUBAGENTS_PARALLEL`). Stop the main
  turn — its subagents stop too.

Works everywhere: in the terminal, in the editor panel, in `execai ui` and
in tasks from the site. On ExecAI models subagents spend the plan like
ordinary turns; on your own keys — your provider.

### ExecAI models by plan, your own keys without one

Your own keys and subscriptions work without an ExecAI plan and even
without signing in: Z.ai, Kimi, Moonshot, OpenAI, Anthropic, OpenRouter,
Claude Code, Codex, a custom provider, Ollama (local and cloud). The keys
stay on your machine; you pay the provider for tokens, not us. You can
connect right from the sign-in screen:

```
/connect zai <key>
/source zai
```

A plan is needed for the ExecAI models (the `execai` source): any plan, the
first 3 days cost 1 ₽. Without one the agent does not call an ExecAI model
and tells you where to get a plan: https://chat.execai.ru/settings/payment.
Paid — just send the message again, the agent re-checks at once. The same
rule applies in `execai run`, in `execai serve` tasks from the web chat and
in the editor panel: the refusal is only for ExecAI models.

The Work and Max plans add sync between machines (below), later the web
console.

The check does not slow the start: the agent uses the saved answer and
refreshes it in the background, then once a day — but only while the
`execai` source is active. On your own keys the plan is not requested at
all, and when you switch to `execai` the agent asks for it right away.
Without a connection to the server the saved answer is valid for up to 7
days.

`execai run` and the plain REPL (`execai chat --plain`) now go through the
active source, like the chat: with your own key — no sign-in and no plan.
If no binary is found for `/source claude-cli` or `codex-cli`, the agent
says plainly that it falls back to the ExecAI models.

### `/plan`

A new command (and `execai plan` in the terminal): the state of the plan,
the tariff, until when it is valid, when it was checked and what it
allows. It also shows whether sync and the web console are available —
they come with the Work and Max plans.

### Migrating from another agent in a minute

Coming from Claude Code, Cursor, Codex CLI, Windsurf, Gemini CLI or GitHub
Copilot — execai now picks up the instructions you wrote for them by
itself.

On the first start in a project that holds `CLAUDE.md`, `.cursorrules`,
`AGENTS.md` and the like, the agent shows what it found, with paths, once
and asks whether to import it into memory. The answer is remembered for the
directory and the question does not come back; a refusal touches nothing.

The same from the terminal and CI:

```
execai import --dry-run              # what goes where; writes nothing
execai import --from claude,cursor   # only these sources
execai import -y                     # without asking
```

In a terminal the command asks `[Y/n]`; without a terminal it does not ask.

New sources: the global `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md` and
`~/.codex/instructions.md` (honouring `CODEX_HOME`), `~/.gemini/GEMINI.md`,
global Windsurf rules, Claude Code project memory from
`~/.claude/projects/`, and in a project — `CLAUDE.local.md`,
`.windsurf/rules/`, `.github/instructions/`. Settings, sessions, logs and
keys of other agents are not read; a file with anything that looks like a
key or a password is skipped, with the line number.

Not carried over: provider keys (`/connect` again), permissions and MCP
servers. Details: `docs/en/migrate.md`.

### Sync between machines

The agent's memory, settings, permissions and provider keys are now the
same on all your machines. Wrote a fact into memory at work — the agent at
home already knows it; connected a key on the laptop — it is on the desktop
too.

```
/sync on        # on the first machine: make up a sync passphrase
/sync on        # on the second: enter the same passphrase — memory, settings and keys arrive
```

Everything is encrypted on the machine with the sync passphrase; the server
keeps only ciphertext — we neither see nor parse what is inside, and the
passphrase cannot be recovered. The server does not even see the names of
the memory files.

What travels: personal memory (`MEMORY.md` and fact files) and the whole
config as one encrypted file — settings, sources together with provider
keys, tool permissions. The config is shared: the active source is also one
for all machines, and sources that existed only on a new machine are added
to the shared ones when it joins. The only thing each machine keeps its own
is the server address. Not synced: the sign-in and the chat history.

Projects sync per project: the `.execai/` folder of a bound project (project
memory and everything in it) travels as one encrypted file, and the
directory may differ on every machine. `/project publish [name]` (and
`execai project publish`) turns the current directory into a project in
the web chat, binds it and sends `.execai/` at once; `/project bind <name>`
on another machine — even in an empty directory — pulls it right away. If
the copies diverged, the newer one wins and the loser stays next to it
(`EXECAI.md.local-<date>` or `.server-<date>`), and the agent says so.
`/sync` shows "Projects: N (names)".

Without sync (and without a plan) the keys can be moved directly, with no
server: `/sync keys export` prints a code and, separately, a 6-word phrase;
`/sync keys import` on the other machine — the sources are there, the
active one does not change.

Sync runs on its own: at the start of the chat, of `execai serve` and of
the editor panel, every 10 minutes, 10 seconds after a change and on exit;
by hand — `/sync now`. Edited on two machines at once — the later edit
wins, and the memory index merges lines from both.

The rest: `/sync` — status, `/sync password` — change the passphrase,
`/sync off` — switch off here, `/sync forget` — delete everything from the
server (the machines keep everything). The same in the terminal:
`execai sync …`. Available on the Work and Max plans; without a plan sync
pauses and touches nothing. Details: `docs/en/sync.md`.

### Tasks from the site — right in the editor panel

A VS Code or ExecAI Studio window with an open project accepts tasks sent
from the web chat or the phone by itself: a separate `execai serve` is no
longer needed. The task appears in the panel as a new chat tagged "from
the web", the whole turn is visible, and the answer goes back to the web
chat. If the agent asks for a permission, the question reaches both the
panel and the site — answer wherever you are.

In the panel menu: the inbox state ("this window accepts", "a background
process accepts" with an **Accept here** button, "another window"), and
binding the project to the folder. A window takes only the tasks of its own
project; `execai ide --no-inbox` switches accepting off. Available on the
Work and Max plans.

### The agent panel in a browser — `execai ui`

The same chat panel as in VS Code and ExecAI Studio now opens in an
ordinary browser — no editor needed:

```
execai ui                 # in the project directory: prints a link and opens the browser
execai ui --no-open       # only print the link (e.g. over SSH with port forwarding)
```

Chats, permissions, choosing the model and the source, tasks from the site —
all as in the editor panel; the browser window accepts the tasks of its
project just like a VS Code window. Closed the tab — the agent keeps
working; opened it again — the panel is there; stop with Ctrl+C in the
terminal.

Security: the panel listens on 127.0.0.1 only, the link carries a one-time
key — on the first visit it turns into a cookie, and the link opens nothing
a second time. Requests from other sites are rejected, and your ExecAI
sign-in never reaches the page. Attached files land in the project's
`.execai/uploads/` and are not synced. Details: `docs/en/ui.md`.
