## What's new

**7.21 fixes a sync fault that could erase a project's memory on all your computers. Please update every computer that syncs, the editor extension and ExecAI Studio.** Sync now decides every file by its content and keeps what it replaces. The release also brings `execai ui` as a window of its own with a new look in three styles, notifications when the agent needs you, project memory that travels with the project, and tasks from the web that run only in this computer's folder.

### A sync fault in 7.15 and earlier: update all your computers

In 7.15 and earlier, sync could erase a project's memory — the whole
`.execai/` folder — on every computer, with no copy left. It took a single
computer where one of these happened:

- the project was bound to an empty folder or to a freshly cloned
  repository (for example `/project unbind`, a new clone, `/project bind`);
- the bound folder was deleted and made again;
- `.execai/` was removed.

That computer took the missing files for a deletion of the whole project
and sent it, and every other computer then removed its `.execai/`. The
personal memory had the same weakness: a memory folder deleted and made
again could delete your notes on every computer.

7.21 never takes this for a deletion. A bound folder with no `.execai/`
files — empty, made again, cloned again, or a binding moved to another
folder — is filled from the server, as on a new computer, and the agent
says so in one line. If the bound folder is not on this computer at all
(deleted, a disk not mounted), the agent says so and writes nothing there.
A memory folder without its index, or with none of its notes left, is
filled from the server too. Deleting one file inside a live `.execai/`, or
some notes while the memory index stays, is still an ordinary change and
reaches your other computers.

**Earlier versions still do it, even alongside 7.21.** An older agent on any
of your computers can still send such a deletion, and an older agent that
receives one still erases its files. A computer with 7.21 that receives one
keeps its files and says so: they stay as they are until you change one of
them (then the project goes up again) or remove `.execai/` by hand. So
update every computer that syncs — and ExecAI Studio, which carries its own
copy of the agent and uses the same settings folder as the agent in the
terminal. The updated editor extension offers to update the agent it runs
to 7.21.

### How sync decides now

- **By content, not by time.** Every file is decided on its own — a memory
  note, each settings file, each file in a project's `.execai/`. The agent
  compares three versions by their content: the one here, the one on the
  server, and the one this computer and the server last agreed on. The time
  of a file plays no part: a clone, an unpacked archive, a restored backup
  or a wrong clock can give a file any time at all.
- **Edits on two computers are both kept.** A project file changed on one
  computer and another file changed on the other end up on both; a project
  is never replaced as a whole by one side. When the same file was changed
  on both, the version already on the server stays, this computer's is
  kept as a copy, and the agent says so.
- **What has not reached the server is never removed silently.** A file
  here is replaced without a word only when it is proven out of date. A
  version the server never had is kept for good: next to the file in a
  project (`EXECAI.md.local-<time>`), and in `sync-unsent/<date>/` in the
  config folder for memory and settings. The agent says in one line how
  many such copies there are and where, and never removes them — only you
  do. To use one, copy it over the file: it goes out as an ordinary change.
- **Deletions and older versions are said.** A file deleted on another
  computer is removed here, and the agent says so. A version from the
  server that goes back to an earlier text — another computer reverted it,
  or an older agent sent an old checkout — keeps the newer one next to the
  file for good (a settings file keeps it in the history), and the agent
  says so.
- **Replaced versions stay on this computer for 30 days.** What the server
  already had and a newer version replaced, or a deletion elsewhere
  removed, goes to `sync-history/` in the config folder: 30 days, up to
  256 MB per project (and as much for the memory and for the settings).
  The line about a removed file names its copy there.
- **An interrupted exchange is finished next time.** A crash, a power cut,
  a full disk or a file that cannot be written, at any point: the copy is
  on disk before anything is replaced, a half-written file is never left
  behind, and the next exchange comes to the same result. Nothing is sent
  half-written, sent twice, or taken for a deletion.
- **The memory index is merged entry by entry.** Every note keeps its line
  in `MEMORY.md`, and a line goes only together with its note: an index the
  model wrote again with fewer lines gets the lines back, and when two
  computers changed it, the lines of both stay. The text you write around
  the lines is decided like any other file.
- **Settings are merged file by file.** A provider key added on one
  computer and a model changed on another both stay. What the agent writes
  by itself — a provider's model list, a fallback model it picked at start when yours was not available — is
  not taken for your change; a model you choose (`/model`, the panel) goes
  to all your computers. When a second computer joins, it no longer
  reports a conflict over settings nobody changed.
- **Sync messages reach the editor panel.** What sync says — a copy kept, a
  file left out, a version taken from the server — appears as a service
  line in the chat of the editor panel (the extension, ExecAI Studio,
  `execai ui`), as it does in the terminal chat and in the output of
  `execai serve`. In the panel, sync commands are typed in a terminal:
  `execai sync`.
- **What cannot be synced is left alone.** A file over the size limit, one
  that cannot be read, or a symbolic link is neither sent nor written over,
  removed or deleted elsewhere; the agent says once what is left out and
  why, and `/sync` lists it.
- **One folder holds one project.** A folder this computer already bound to
  another project is not bound again: `/project bind`, `/project publish`
  and the editor panel say which project has it.
- **One exchange at a time.** The chat, `execai serve` and the editor no
  longer sync at the same time and undo each other's changes (for example,
  a `/sync off`).
- **Keeping this computer's key** (`/sync on` when the keys differ) names
  beforehand the projects whose memory is deleted from the server, and
  deletes only what it named, at the version it showed.
- **A server without a sync key pauses sync.** When the server says it has
  no sync key — sync was deleted from another computer, or something in
  the way answered for the server — sync pauses here and says so; nothing
  is reset or switched off. Check with `/sync`.

The whole guide, with a table of every case: `docs/en/sync.md`.

### What sync still cannot protect

- **A save at the very moment of a replacement.** The model's Write and
  Edit tools, `/project memory` and a memory import take a short lock that
  sync respects. Other writers do not: commands the model runs in the shell
  (`>>`, `sed -i`), an external source that writes files itself
  (`claude-cli`, `codex-cli`), the agent's own settings writes (`/connect`,
  `/model`), your editor, a script. If one of them saves a file in exactly
  the moment between sync's last check of it and the replacement, that one
  save is replaced by the server's version and lost, unless it is that
  version.
- **Folders the file system cannot tell apart** — network drives and some
  other mounts (the guide names them). There a folder is known by its path
  only: a missing file is not taken for a deletion and comes back from the
  server, and an older version put back is not taken for an edit.
- **Limits of the history.** A return to an earlier text is recognized
  among the last 64 agreed versions of a file; going back further counts as
  an ordinary edit, and the newer text stays in the other computers'
  history for 30 days only. Past 30 days, or past 256 MB per area, the
  oldest versions in the history go; the agent says so if any younger than
  30 days had to go.
- **Older agents.** A computer or an ExecAI Studio still on 7.15 or earlier
  behaves the old way (see above).

### Upgrading from 7.15

- **Nothing is deleted on the first start.** 7.21 reads the state the
  earlier version left, and the first exchange compares your files with the
  server. If nothing changed, here or on the server, since the old
  version's last exchange, it sends nothing, takes nothing and makes no
  copies.
- **On that first exchange your folders are known by their path only**;
  from then on the agent also records which folder each project and the
  memory live in. Your edits go up as usual, but a file missing here is
  brought back from the server instead of being deleted everywhere. If you
  deleted something under the old version and the deletion had not reached
  the server yet, delete it again after the first exchange.
- **Changed both here and on another computer.** A project or the
  settings changed on both sides since the old version's last exchange have
  nothing to compare with file by file yet: the server's version stays, and
  what differs here is kept — next to the file in a project, in
  `sync-unsent/` for the settings — with a line saying so.
- **Old copies stay.** Copies left by earlier versions (`*.local-*`,
  `*.server-*`) are never removed, and `/sync` counts them. New files of
  sync's own appear in the config folder: `sync-bases.json` next to
  `sync.json`, the lock files `sync.lock` and `write.lock`, and the
  `sync-unsent/` and `sync-history/` folders.
- A computer with 7.21 and one with an earlier version still sync with each
  other, but only the one with 7.21 has the protections above.

### Notifications in the terminal chat

Give the agent a task and switch to the browser: when the turn finishes,
when the agent waits for your approval of a tool, or when it asks you a
question, you get a notification — `ExecAI: turn finished — my-project`,
`ExecAI is waiting for approval: Bash`, `ExecAI has a question`. The text
names the project folder or the tool and nothing else: no prompt, no
answer, no paths.

- **Only when you are away.** The chat listens to the terminal's focus
  reports and stays quiet while you look at it. A terminal that never
  reports focus still gets a notification for a turn of 30 s or more since
  your last keystroke and for a question left unanswered for 15 s.
- **One popup, the right one.** Terminals with notifications of their own
  (OSC 9 / OSC 777) show it themselves; otherwise `notify-send` on Linux,
  `osascript` on macOS, a toast on Windows. The terminal bell rings too.
- **Over SSH** nothing is started on the remote machine: the notification
  travels through the terminal to your computer.
- One question — one notification; a turn you stopped yourself is not
  announced.
- Background work (`/loop`, wake-ups the agent schedules itself) is not
  announced turn by turn: only a question inside it, an error or the step
  limit, and its end.

`/notifications` shows the mode and what this computer uses:
`/notifications system` (default), `bell` (terminal only), `off`, and
`/notifications test` sends one right away. Also
`execai config set notifications=bell`. The setting stays on each
computer — sync does not carry it. Details: `docs/en/notifications.md`.

### The editor panel

While the editor window is in the background, a notification inside it is
seen by nobody: with the updated editor extension the agent shows a desktop
notification instead (on your own computer; in a remote session the
in-editor one stays).

### `execai ui`: a window of its own and a new look

`execai ui` — the chat panel without an editor — now opens as a window of
its own and has a layout made for it.

- **A window, not a tab.** When Google Chrome, Chromium, Microsoft Edge,
  Yandex Browser, Brave or Vivaldi is installed, the panel opens as a window
  with no tabs and no address bar, with its own button on the taskbar. With
  no such browser (only Safari, only Firefox), or when the window does not
  open, it opens as a browser tab, as before. `--window` asks for a window
  only, `--browser` for a tab, `--no-open` only prints the address.
- **One window per folder.** A second `execai ui` in the same folder shows
  the window that is already open. Every folder keeps its own address from
  run to run. Closing the window stops the panel (the browser asks first
  while a turn is running); `execai ui --stop` stops it from another
  terminal.
- **A shortcut.** `execai ui --install-shortcut` puts ExecAI into the
  applications menu on Linux, `~/Applications` on macOS and the Start menu
  on Windows; it opens the folder of the last run.
- **Three looks, light and dark.** The page is laid out for a wide window:
  the chats on the left, the conversation in the middle, the agents and the
  changed files on the right; in a narrow window the side panels slide out.
  Choose between Workbench, Conversation and Teletype under "Look and
  theme", each with a light and a dark theme; until you choose, the theme
  follows the system. The side panel folds away. Inside an editor the panel
  looks as before.
- **Keys.** A permission request is answered from the keyboard: `Y` once,
  `A` this tool until the end of the chat, `S` exactly this call, `F`
  always, `N` or Esc to refuse, Enter for once; from an empty message field
  Ctrl+Enter allows once. The letters work in any keyboard layout. Esc
  stops a turn, Ctrl+N starts a new chat.
- **The way in.** The window gets its one-time key in a file only you can
  read, not on the browser's command line. If the one-time link is used a
  second time by someone who is not signed in, the agent says so in the
  terminal, signs every browser out, refuses the waiting permission
  requests and stops the running turns. On Linux without a graphical
  session (over SSH) nothing is started: the link is printed. `execai ui
  --code` gives a one-time code to sign in by hand — for Safari's "Add to
  Dock" or a browser that did not show the page.
- **Smaller things.** The first message in a new project no longer
  vanishes from the page. A refused tool call is shown as refused, not as
  done. A message with attachments opened from the history shows what you
  typed and the files, not the whole prompt. Every finished answer has its
  copy button. Links clicked in the window open in your usual browser.
- **Notifications.** The panel announces a finished turn or a waiting
  question of the chat on screen too, and also when the window is behind
  another one (the 🔔 button in the header asks for permission). A question
  raises one desktop notification, not two.
- **Where it was tried.** The window was tried on Linux with Chromium and
  Google Chrome. On macOS and Windows it is built and covered by tests but
  not yet tried on real machines: if the window gives trouble there,
  `execai ui --browser` opens the tab as before.

The guide: `docs/en/ui.md`.

### Project memory travels with the project

The agent now keeps project memory in `.execai/EXECAI.md` — the folder that
sync carries between your computers — so what it learns about a project on
one machine is there on the other.

- A root `EXECAI.md` is still read, as project instructions; the agent does
  not write to it unless you ask.
- `/project memory` copies a root `EXECAI.md` into `.execai/` so that it
  travels too, and says what is still needed for that: binding the folder
  to a project, or turning sync on. The root file stays where it is.
- Both files are loaded; the same text is not loaded twice.

### Tasks from the web run in this computer's folder

- A task from the web chat or the phone runs only in the folder this
  computer bound to the project. A project bound only on another computer
  is refused with a clear reason instead of running somewhere else.
- `/project`, the editor panel and the getting-started list show only this
  computer's folders, and unbinding acts only on them. `/project` also
  recognizes a folder bound through a symbolic link.

### Fixes

- The editor panel speaks the interface language throughout: the
  permission buttons, the sources to connect, the security levels, signing
  in and connecting a source, and the agent's notices and errors were in
  Russian before, whatever the language.
- Errors of the models and of the plan — a wrong provider key, a plan
  limit, a model not installed in Ollama, a missing `claude` or `codex`
  CLI — are shown in the interface language in the chat, in the panel and
  in the answer to a task from the web. Sign-in hints say `execai login`.
- `EXECAI_LOCALE` now wins over the language saved in the settings, which
  sync shares between your computers.
- `execai sync` in a shell exits with code 1 and prints the reason to
  stderr when sync is busy in another ExecAI process or the command is
  refused for the plan or the sign-in; it used to exit with 0.
- `/machine` right after signing in no longer says there is no plan while
  one is active: it checks the plan first and says "plan being checked"
  while it cannot.
- After `/project publish` or `/project bind` the result is shown as a
  message of its own, not inside the question that follows.
- The hint under a question names only the digits of its options.
- The one-time move of the settings from the folder of a much older
  version no longer deletes that folder: once everything is copied, it is
  renamed and kept.
