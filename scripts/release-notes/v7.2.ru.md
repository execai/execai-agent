## Что нового

**7.2 — первая публичная версия седьмой линейки.** В ней всё разом: модели ExecAI по подписке (свои ключи — без неё), переезд с другого агента, синхронизация с паролем и проектами, задачи с сайта прямо в панели редактора, параллельные субагенты с наблюдением за ними и панель агента в браузере (`execai ui`). Плагин VS Code 0.2.36 и ExecAI Studio обновляются вместе с агентом.

### Субагенты: несколько агентов работают одновременно

Агент раздаёт подзадачи субагентам, и они идут параллельно: «изучи
обработчики», «проверь тесты», «найди, где читается конфиг» — три
субагента за время одного. У каждого свой цикл, свой контекст и свой
транскрипт; основному агенту возвращается только итог.

- **Читать или делать.** По умолчанию субагент только читает. В режиме
  `write` он правит файлы и запускает команды — и спрашивает разрешение
  там же, где основной агент, с пометкой «спрашивает агент «имя»».
- **В фоне.** Субагент можно запустить и не ждать: агент продолжает
  работу, а итог приходит сам отдельным сообщением, когда субагент
  закончит (или агент дожидается его инструментом `TaskWait`).
- **Своя модель и каталог.** `model: fast` — самая дешёвая модель
  текущего источника для простого поиска; можно назвать и конкретную.
  Каталог — подпапка проекта, выше проекта субагент не поднимается.
- **Видно, кто что делает.** В терминале над вводом — блок «Агенты»
  (состояние, шаг, последний инструмент, время), в статусной строке —
  «агенты: 2▶ 1✓». `/agents` — список с итогами, `/agents open <n>` —
  всё, что субагент делал, `/agents stop <n>` — остановить. В панели
  VS Code, ExecAI Studio и `execai ui` — тот же список с вкладкой
  транскрипта, на карточке компьютера в веб-панели — сколько работает и
  что готово.
- **Пределы.** По умолчанию 15 шагов и 5 минут на субагента (шагов можно
  до 50), одновременно до 4 (`EXECAI_SUBAGENTS_PARALLEL`). Остановили
  основной ход — останавливаются и его субагенты.

Работает везде: в терминале, в панели редактора, в `execai ui` и в
задачах с сайта. На моделях ExecAI субагенты расходуют план как обычные
ходы, на своих ключах — ваш провайдер.

### Модели ExecAI — по подписке, свои ключи — без неё

Свои ключи и подписки работают без подписки ExecAI и даже без входа: Z.ai,
Kimi, Moonshot, OpenAI, Anthropic, OpenRouter, Claude Code, Codex, свой
провайдер, Ollama (локальный и облачный). Ключи остаются на твоей машине,
токены оплачиваешь провайдеру, не нам. Подключить можно прямо с экрана входа:

```
/connect zai <ключ>
/source zai
```

Подписка нужна для моделей ExecAI (источник `execai`): любой план, первые
3 дня — за 1 ₽. Без неё агент не зовёт модель ExecAI, а пишет, где оформить
план: https://chat.execai.ru/settings/payment. Оплатил — просто отправь
сообщение ещё раз, агент перепроверит сразу. То же правило — в
`execai run`, в задачах `execai serve` из веб-чата и в панели редактора:
отказ только на моделях ExecAI.

На планах «Работа» и «Макс» — синхронизация между компьютерами (ниже),
позже — веб-пульт.

Проверка не тормозит запуск: агент берёт сохранённый ответ и обновляет его в
фоне, затем раз в сутки — но только пока активен источник `execai`. На своих
ключах план не запрашивается вовсе, а при переключении на `execai` агент
спросит его сразу. Без связи с сервером сохранённый ответ действует до 7 дней.

`execai run` и простой REPL (`execai chat --plain`) теперь идут через
активный источник, как и чат: со своим ключом — без входа и без подписки.
Если для `/source claude-cli` или `codex-cli` не найден бинарь, агент прямо
скажет, что откатывается на модели ExecAI.

### `/plan`

Новая команда (и `execai plan` в терминале): состояние плана, тариф, до
какого числа действует, когда проверяли и что разрешено. Там же видно,
доступны ли синк и веб-пульт — они идут с планами «Работа» и «Макс».

### Переезд с другого агента за минуту

Пришли из Claude Code, Cursor, Codex CLI, Windsurf, Gemini CLI или GitHub
Copilot — инструкции, которые вы им писали, execai теперь забирает сам.

При первом запуске в проекте, где лежат `CLAUDE.md`, `.cursorrules`,
`AGENTS.md` и подобные, агент один раз показывает находки с путями и
спрашивает, импортировать ли их в память. Ответ запоминается для каталога,
повторно вопрос не появляется; отказ ничего не трогает.

То же из терминала и CI:

```
execai import --dry-run              # что и куда ляжет; ничего не пишет
execai import --from claude,cursor   # только эти источники
execai import -y                     # без вопроса
```

В терминале команда спрашивает `[Y/n]`, без терминала — не спрашивает.

Новые источники: глобальные `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md` и
`~/.codex/instructions.md` (с учётом `CODEX_HOME`), `~/.gemini/GEMINI.md`,
глобальные правила Windsurf, память проекта Claude Code из
`~/.claude/projects/`, а в проекте — `CLAUDE.local.md`, `.windsurf/rules/`,
`.github/instructions/`. Настройки, сессии, логи и ключи других агентов не
читаются; файл, где есть что-то похожее на ключ или пароль, пропускается с
номером строки.

Не переносятся ключи провайдеров (`/connect` заново), разрешения и
MCP-серверы. Подробно: `docs/ru/migrate.md`.

### Синхронизация между компьютерами

Память агента, настройки, разрешения и ключи провайдеров теперь одинаковые
на всех ваших компьютерах. Записали факт в память на работе — дома агент
его уже знает; подключили ключ на ноутбуке — он есть и на рабочем.

```
/sync on        # на первом компьютере: придумать пароль синхронизации
/sync on        # на втором: ввести тот же пароль — память, настройки и ключи приехали
```

Всё шифруется на компьютере паролем синхронизации, на сервере лежит только
зашифрованное — что внутри, мы не видим и не разбираем; восстановить пароль
тоже нельзя. Даже названия файлов памяти сервер не видит.

Едут: личная память (`MEMORY.md` и файлы-факты) и весь конфиг одним
зашифрованным файлом — настройки, источники вместе с ключами провайдеров,
разрешения инструментов. Конфиг общий: активный источник тоже один на все
компьютеры, а источники, которые были только на новом компьютере, при
подключении добавляются к общим. Своим у каждого компьютера остаётся только
адрес сервера. Не едут: вход, история бесед.

Проекты синхронизируются по проектам: папка `.execai/` привязанного
проекта (память проекта и всё, что там лежит) едет одним зашифрованным
файлом, а каталог на каждом компьютере может быть свой.
`/project publish [имя]` (и `execai project publish`) делает из текущего
каталога проект в веб-чате, привязывает и сразу отправляет `.execai/`;
`/project bind <имя>` на другом компьютере — даже в пустом каталоге —
сразу забирает её. Если копии разошлись, побеждает более свежая, а
проигравшая остаётся рядом (`EXECAI.md.local-<дата>` или
`.server-<дата>`), и агент об этом говорит. В `/sync` — «Проекты: N (имена)».

Без синхронизации (и без тарифа) ключи можно перенести напрямую, без
сервера: `/sync keys export` показывает код и отдельно фразу из 6 слов, на
другом компьютере `/sync keys import` — источники на месте, активный не
меняется.

Синхронизация идёт сама: при запуске чата, `execai serve` и панели в
редакторе, каждые 10 минут, через 10 секунд после изменения и при выходе;
вручную — `/sync now`. Правка на двух компьютерах сразу — побеждает более
поздняя, а индекс памяти сливает строки с обоих.

Остальное: `/sync` — состояние, `/sync password` — сменить пароль,
`/sync off` — выключить здесь, `/sync forget` — удалить всё с сервера (на
компьютерах всё останется). В терминале то же: `execai sync …`.
Доступно на тарифах «Работа» и «Макс»; без тарифа синхронизация встаёт на
паузу и ничего не трогает. Подробно: `docs/ru/sync.md`.

### Задачи с сайта — прямо в панели редактора

Окно VS Code или ExecAI Studio с открытым проектом само принимает задачи,
отправленные из веб-чата или с телефона: отдельный `execai serve` больше не
нужен. Задача появляется в панели новым чатом с меткой «с сайта», весь ход
виден, а ответ уходит обратно в веб-чат. Если агент спрашивает разрешение,
вопрос приходит и в панель, и на сайт — отвечайте там, где вы сейчас.

В меню панели: состояние приёма («принимает это окно», «принимает фоновый
процесс» с кнопкой «Принимать здесь», «другое окно»), привязка проекта к
папке. Окно берёт только задачи своего проекта; `execai ide --no-inbox`
выключает приём. Доступно на тарифах «Работа» и «Макс».

### Панель агента в браузере — `execai ui`

Та же панель чата, что в VS Code и ExecAI Studio, теперь открывается в
обычном браузере — редактор не нужен:

```
execai ui                 # в каталоге проекта: печатает ссылку и открывает браузер
execai ui --no-open       # только напечатать ссылку (например, по SSH с пробросом порта)
```

Чаты, разрешения, выбор модели и источника, задачи с сайта — всё как в
панели редактора; окно браузера принимает задачи своего проекта так же, как
окно VS Code. Закрыли вкладку — агент продолжает работу, открыли снова —
панель на месте; остановить — Ctrl+C в терминале.

Безопасность: панель слушает только 127.0.0.1, в ссылке одноразовый ключ —
при первом заходе он меняется на cookie, и повторно ссылка ничего не
открывает. Запросы с других сайтов отклоняются, вход в ExecAI до страницы не
доходит. Приложенные файлы ложатся в `.execai/uploads/` проекта и не
уезжают в синхронизацию. Подробно: `docs/ru/ui.md`.

### Мелочи

- Z.ai разрешил использовать GLM Coding Plan в нашем агенте — грозное
  предупреждение при `/connect zai` заменено короткой строкой: агент
  представляется своим именем, не выдавай его за Claude Code.
- `execai serve`, `execai run` и панель редактора говорят на языке системы
  (раньше всегда по-английски).

- `/memory import` показывает, в какой файл памяти ляжет каждая находка, и
  новая память видна со следующего хода, без перезапуска.
- Одинаковый `CLAUDE.md` из двух проектов больше не теряется на втором.
- После подключения своего ключа без перезапуска чат больше не остаётся
  без системного промта и памяти.
