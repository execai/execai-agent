# Синхронизация между компьютерами

Память агента, настройки, разрешения и ключи провайдеров — одинаковые на
всех ваших компьютерах. Записали факт в память на работе — дома агент его
уже знает; подключили ключ Z.ai на ноутбуке — он есть и на рабочем
компьютере. Всё шифруется на компьютере паролем синхронизации; на сервере
лежит только зашифрованное — что внутри, мы не видим и не разбираем.

Синхронизация доступна на тарифах «Работа» и «Макс»:
https://chat.execai.ru/settings/payment

## 1. Первый компьютер

В чате:

```
/sync on
```

или в терминале:

```bash
execai sync on
```

Агент попросит придумать пароль синхронизации — не короче 10 знаков. Его
нужно будет ввести на других компьютерах. **Восстановить пароль нельзя**: у
нас его нет. Запишите его в менеджер паролей.

После этого агент сразу отправит память и настройки и покажет, что
синхронизируется:

```
Синхронизация включена.
Синхронизируется: память (файлов: 12), настройки и ключи провайдеров — всё зашифровано на этом компьютере.
```

## 2. Второй и следующие компьютеры

Установите агента, войдите в тот же аккаунт ExecAI и наберите `/sync on`.
Агент увидит, что синхронизация уже включена, и попросит пароль с первого
компьютера. Ввели — память, настройки и ключи провайдеров приехали.
Конфиг общий для всех компьютеров: активный источник тоже приходит с
первого. Источники, которые были только на этом компьютере, не пропадают —
они добавятся к общим и уедут на остальные.

Если пароль не тот, агент так и скажет: «Пароль не подошёл», — и спросит
ещё раз.

Если на этом компьютере уже был свой ключ шифрования (например, после
`/key new`) и он не совпадает с ключом на сервере, агент предложит выбор:

1. взять ключ с сервера — ваш прежний ключ сохранится рядом
   (`sync.key.old-<дата>`);
2. оставить свой и заменить им серверный — всё на сервере перезапишется
   данными этого компьютера, а остальные компьютеры попросят пароль ещё раз.

Обычно нужен первый вариант.

## 3. Что синхронизируется, а что нет

| Синхронизируется | Не синхронизируется |
|---|---|
| Личная память: `memory/` — `MEMORY.md` и файлы-факты, по файлу | Адрес API (`api_base`) — у каждого компьютера свой |
| Конфиг одним зашифрованным файлом: `config.json`, `subscriptions.json` (источники вместе с ключами провайдеров), `permissions.json` | Вход в ExecAI (`credentials.json`), идентификатор машины |
| Папка проекта `.execai/` целиком (память проекта `EXECAI.md` и всё, что там лежит) — для проектов, привязанных к веб-чату, см. раздел 6 | История бесед, кэш моделей, план, список проектов, `serve.pid` |

Конфиг уходит на сервер одним зашифрованным файлом целиком — что внутри, мы
не видим и не разбираем. Единственное, что остаётся своим у каждого
компьютера, — адрес сервера `api_base`.

Где лежат файлы:

| ОС | Каталог |
|---|---|
| Linux | `~/.config/execai/` |
| macOS | `~/Library/Application Support/execai/` |
| Windows | `%APPDATA%\execai\` |

Файл больше 256 КБ остаётся только на своём компьютере — `/sync` скажет,
какой. Всего на сервере помещается 32 МБ и до 2000 файлов.

## 4. Как это защищено

- Каждый файл памяти и весь конфиг (с ключами провайдеров) шифруются на
  компьютере вашим ключом до отправки. Ключ лежит в `sync.key` (доступ
  только у владельца).
- На сервер ключ попадает только запертым вашим паролем. Пароль сервер не
  видит, поэтому ни прочитать, ни восстановить ничего не может.
- Названия файлов памяти тоже скрыты: сервер видит бессмысленный
  идентификатор, настоящее имя — внутри зашифрованного.
- Что сервер всё-таки знает: сколько файлов и какого они размера, когда
  менялись, и про каждый компьютер — названия подключённых источников
  (например, «ExecAI · Z.ai Coding Plan · Moonshot»), активный источник и
  версию агента. Сами ключи провайдеров сервер не видит — они только внутри
  зашифрованного конфига.

## 5. Перенос ключей без синхронизации — запасной путь

С включённой синхронизацией ключи провайдеров приезжают сами, вместе с
конфигом. Если синхронизации нет (или нет тарифа), ключи можно перенести
напрямую — без сервера и без тарифа.

На компьютере, где ключи есть:

```
/sync keys export
```

Агент покажет код переноса и отдельно — фразу из 6 слов. Передайте их на
другой компьютер сами (мессенджер, флешка), лучше разными путями: код и
фраза вместе открывают ваши ключи.

На другом компьютере:

```
/sync keys import
```

Вставьте код, затем введите фразу. Новые источники добавятся, активный
источник не изменится — переключиться: `/source <имя>`. Если такой источник
уже был с другим ключом, остаётся тот, что подключили позже.

В терминале то же самое: `execai sync keys export`, `execai sync keys import`.
Для переноса ключей ни вход, ни тариф не нужны.

## 6. Проекты

Конфиг и память — общие для всех компьютеров, а проекты синхронизируются
по проектам. Проект в веб-чате связывается с каталогом на компьютере
привязкой, и у каждого компьютера каталог может быть свой: на ноутбуке
`~/work/app`, на рабочем — `D:\src\app`. Папка `.execai/` привязанного
проекта едет одним зашифрованным файлом.

**Свой каталог — в веб-чат.** В каталоге проекта:

```
/project publish [имя]
```

Агент создаст проект в веб-чате (имя по умолчанию — имя каталога), привяжет
к нему этот каталог и сразу отправит `.execai/`. В терминале:
`execai project publish [имя]`.

**Проект из веб-чата — в каталог.** На другом компьютере, в нужном каталоге
(можно в пустом):

```
/project bind <имя>
```

Агент привяжет каталог и сразу заберёт `.execai/` с сервера.

Если `.execai/` есть и здесь, и на сервере и они разные, побеждает более
свежая копия. Проигравшая не пропадает: её файлы остаются рядом —
`EXECAI.md.local-<дата>` (была здесь) или `EXECAI.md.server-<дата>` (была на
сервере), — и агент скажет об этом. Эти копии никуда не уезжают.

Удалили файл в `.execai/` — он удалится и на других компьютерах. Сняли
привязку (`/project unbind`) — данные проекта на сервере остаются: проект
может быть привязан на других компьютерах. Файлы проекта синхронизируются
при включённой синхронизации; `/sync` показывает «Проекты: N (имена)».
На один проект на сервере — до 1 МБ (после сжатия).

## 7. Когда синхронизируется

- при запуске чата, `execai serve` и панели в редакторе;
- каждые 10 минут, пока агент запущен;
- через 10 секунд после изменения памяти, настроек, источников, разрешений
  или папки `.execai/` привязанного проекта;
- сразу после `/project bind` и `/project publish` — для этого проекта;
- при выходе;
- по команде `/sync now`.

Если файл поменяли на двух компьютерах сразу, побеждает более поздняя
правка. Индекс памяти `MEMORY.md` при этом не теряет строк: строки с обоих
компьютеров сливаются. Удалённый файл памяти удаляется и на других
компьютерах, но если его успели поправить после удаления — правка
сохраняется.

## 8. Команды

| В чате | В терминале | Что делает |
|---|---|---|
| `/sync` | `execai sync` | состояние: включена ли, когда был обмен, что едет и что нет |
| `/sync on` | `execai sync on` | включить на этом компьютере |
| `/sync now` | `execai sync now` | синхронизировать сейчас |
| `/sync password` | `execai sync password` | сменить пароль; на других компьютерах ничего делать не нужно |
| `/sync off` | `execai sync off` | выключить на этом компьютере; данные на сервере остаются |
| `/sync forget` | `execai sync forget` | удалить всё с сервера (спросит слово «удалить») |
| `/sync keys export` | `execai sync keys export` | запасной путь без сервера и тарифа: код переноса ключей и фраза к нему |
| `/sync keys import` | `execai sync keys import` | принять ключи по коду и фразе |
| `/project publish [имя]` | `execai project publish [имя]` | сделать из этого каталога проект в веб-чате и отправить `.execai/` |
| `/project bind <имя>` | — | привязать этот каталог к проекту из веб-чата и забрать `.execai/` |

## 9. Удалить данные с сервера

`/sync forget` удаляет с сервера ключ шифрования, всю синхронизированную
память, конфиг (с ключами провайдеров) и список компьютеров. На самих компьютерах всё остаётся.
Остальные компьютеры заметят это при следующей проверке и выключат
синхронизацию у себя — обратно они ничего не отправят. Удаление работает и
без тарифа.

## 10. Если что-то не так

- **«Синхронизация доступна на тарифах «Работа» и «Макс»»** — на текущем
  тарифе синхронизации нет. Если тариф закончился, синхронизация встаёт на
  паузу: файлы на компьютере не трогаются. После продления она продолжится
  сама в течение суток, а сразу — по `/sync now`.
- **«Пароль не подошёл»** — проверьте раскладку и Caps Lock. Пароль не
  восстанавливается; если он потерян, удалите данные с сервера
  (`/sync forget`) и включите синхронизацию заново — память на компьютерах
  останется.
- **«На другом компьютере сменили ключ синхронизации»** — там выбрали
  «оставить свой ключ». Наберите `/sync on`, введите пароль и выберите
  «взять ключ с сервера».
- **«Файлов на сервере, которые не открываются здесь»** — они зашифрованы
  другим ключом; то же решение: `/sync on`.
