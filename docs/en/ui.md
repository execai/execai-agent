# The agent panel in a window of its own or in a browser — `execai ui`

- **What it is.** The same chat panel as in VS Code and ExecAI Studio, without an editor: chats, permissions, models and sources, tasks from the site. The agent itself serves the page on 127.0.0.1; a browser of this computer shows it — as a window of its own or as a tab.
- **Run.** `execai ui` in the project directory (or `execai ui --cwd DIR`). Stop: close the window, press Ctrl+C in the terminal (the window closes too) or run `execai ui --stop` in another terminal.
- **A window of its own.** When Google Chrome, Chromium, Microsoft Edge, Yandex Browser, Brave or Vivaldi is installed, the panel opens as a window without tabs and without an address bar, with its own button on the taskbar. The default browser is used when it is one of these, otherwise the first one found. To choose yourself, set the `EXECAI_UI_BROWSER` variable or the `ui_browser` key in `config.json`: a name (`chrome`, `chromium`, `edge`, `yandex`, `brave`, `vivaldi`), a command or the full path to the program (a path from the current folder is not taken). It is a setting of this computer: sync does not carry it. When the named browser is missing, the agent says so and picks one itself. The window has been tried live with Chromium and Google Chrome on Linux; with Microsoft Edge, Yandex Browser, Brave and Vivaldi, and on Windows and macOS, not yet.
- **A tab instead of the window.** When there is no such browser (only Safari on a Mac, only Firefox on Linux) or the window did not open, the panel opens as a tab of the default browser with a one-time link, and one line in the terminal says which browsers give a window. When the browser started but has not shown the panel within twenty seconds, the terminal tells how to sign in: with a code or with the link. On Linux without a graphical session (`DISPLAY` and `WAYLAND_DISPLAY` are empty — a server reached over SSH, say) nothing is started, neither a browser nor the system program that opens links: the link is printed, and you open it yourself. The tab may be closed — the agent runs until Ctrl+C.
- **Flags.** `--window` — a window only: when there is no suitable browser, or it gave no window, an error. `--browser` — always a tab. `--no-open` — open nothing, only print the address. `--port N` — your own port. `--cwd DIR` — the project folder, `--last` — the folder of the last run. `--stop` — stop the panel of this folder, `--stop --all` — the panels of all folders. `--code` — a one-time code to sign in with.
- **One window per folder.** A second `execai ui` in the same folder starts no second server: it shows the window that is already open, says the panel is already open and exits. Different folders have their own windows and addresses. While a turn is running, the browser asks before it closes the window: closing the window stops the panel.
- **Stopping from another terminal.** `execai ui --stop` in the project folder (or with `--cwd DIR`) stops its panel the way Ctrl+C does: the window closes, the agent ends. It also works for a panel that was started from the shortcut and stayed in the background without a window. `execai ui --stop --all` stops the panels of all folders. When nothing is running, the command says so. It sends no signals to processes: it asks the panel at its own address with a secret from the state file, which only its owner can read, and takes the panel for stopped once it has let the folder go.
- **The address.** Every folder has its own port in the range 23750–23769: it is worked out from the folder's path, so the folder's address — `http://127.0.0.1:23757/`, say — is the same from run to run. When the port is taken (the panel of another folder, another program), the next one is used.
- **A launcher shortcut.** `execai ui --install-shortcut` creates an ExecAI shortcut: in the applications menu on Linux (`~/.local/share/applications/execai-ui.desktop`), in `~/Applications` on macOS (`ExecAI.app`), in the Start menu on Windows. It opens the folder of the last run. Until there is one it starts nothing — the home folder does not become the project — and tells by a notification how to name a folder: run `execai ui` in the project folder, or make a shortcut for a folder with `--install-shortcut --cwd DIR`. Remove it with `execai ui --remove-shortcut` (with the same `--cwd`); only what this command made is removed. The shortcut is meant for the window: without a suitable browser it opens a tab, and the panel keeps running in the background until it is stopped: `execai ui --stop --all`.
- **Safari.** Safari cannot be told from a terminal to open a page as a window, but you can do it yourself: in Safari on macOS 14 or later, File → Add to Dock. The page is ready for that: a name, an icon, the colours of the window. The Dock icon opens the panel's address without the link from the terminal and keeps its cookies apart, so after a new start of `execai ui` it shows the sign-in page: run `execai ui --code` in a terminal, in the project folder, and enter the code it prints. The code is made by that command, and is good for five minutes and for one sign-in.
- **The window's profile.** The window is a browser process of its own with its own profile: none of your extensions, bookmarks or logins. That is how the agent sees that the window was closed: at once, or within about ten seconds on macOS, where a browser goes on running without windows. The profile lives in the agent's config directory, `ui-window/<browser>-<folder>`: about 10 MB per project folder and 2–3 MB of cache. Sync does not touch it; you can delete it whenever the window is closed. Links in the panel open in your usual browser.
- **Security.** It listens on 127.0.0.1 only. The way in is a one-time 32-byte key that the first visit swaps for an HttpOnly SameSite=Strict cookie, so the link opens nothing a second time. The window gets the key in a file only you can read — it is not among the arguments of the started browser, which every program on the computer can see. A tab gets the address with the key through the system program that opens links, as an argument, where other programs of the computer can see it for a fraction of a second (without a graphical session that program is not called, and the key is in the terminal only). Against this there is an alarm, not a lock: if somebody without a sign-in comes with a key that was already used — at any time while the panel runs — or the key is used and no panel page connects within 15 seconds, the agent drops every sign-in, stops the running turns, refuses the waiting permission requests and says so in the terminal. Whoever came in first may have sent the agent a message before that — after such a line, look at what the chats did last; and if nobody ever comes second (you did not open the link) while the other side keeps a page connected, there is no alarm. Clicking the link again in the same browser, or reloading the page, rings nothing: they carry the sign-in cookie. Without the cookie the panel's address gives only the sign-in page, the icon and the web app description — nothing about the project. There is no one-time code until `execai ui --code` asks for one; it is good for five minutes and one sign-in, and five wrong tries burn it. A code cannot be guessed that way, but a program on the same computer can burn every code that is issued with wrong tries — signing in by code then fails for as long as it does so. Enter the code only on the page at the address printed next to it. Requests from other sites and other host names are refused, the page can reach nothing but this agent, and your ExecAI login never reaches the page.
- **The look.** The page is laid out for a wide window: the chats on the left, the conversation in the middle, the agents and the changed files on the right; in a narrow window the side panels slide out instead. There are three looks — Workbench (dense and calm, like an editor), Conversation (soft and roomy, the chat in the middle) and Teletype (monospaced, with a yellow marker) — each with a light and a dark theme; until you choose, the theme follows the system. "Look and theme", next to the account, switches both, and this browser remembers the choice. The side panel folds away with its button and stays folded. Inside an editor the panel looks as before and follows the editor's theme.
- **Keys.** When the agent asks for permission, the answers show their keys: `Y` — once, `A` — this tool until the end of the chat, `S` — exactly this call until the end of the chat, `F` — always, `N` or Esc — refuse; Enter also means once. The letters work in any keyboard layout and do nothing while the cursor is in the message field; from an empty message field Ctrl+Enter (⌘ Enter on a Mac) allows once. A key pressed in the first third of a second after a request appears is not taken for an answer, and only a request that is on screen is answered. With no request waiting, Esc stops the turn. Ctrl+N starts a new chat (in a tab the browser keeps this key for itself).
- **Getting started and My machine.** The panel menu has the five getting-started steps with their marks and the machine card (models, sync, taking tasks) with a QR code for the phone: the same as `/start`, `/machine` and `/phone` in the chat — [more](start.md).
- **Notifications.** The 🔔 button in the page header asks the browser for permission. After that, when a chat finishes its turn or waits for your answer while the window or the tab is out of sight, a desktop notification says so; a click opens that chat — [more](notifications.md).
- **Files** you attach in the panel are saved in `.execai/uploads/` of the project; project sync does not send them.
- **Over SSH:** `ssh -L 8765:127.0.0.1:8765 host`, run `execai ui --port 8765 --no-open` there and open the printed link here.
